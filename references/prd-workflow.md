# PRD 与非标准埋点表整理

## 1. 读取材料并判断每个模块

飞书 PRD、内嵌表格和截图优先使用已授权的 CLI/API，以本人 `user` 身份访问；可用时加载客户端的 lark-doc / lark-sheets 等对应技能。没有这些工具时复用本人已登录 Chrome。授权或网络问题先区分原因，不把短期令牌到期当作必须重新登录。原文、评论、权限和原型始终只读。

结合正文、变更记录、删除线、评论、原型和图片，确定本期 C 端范围、应用端、负责人及排除项。一个 PRD 可同时有下列情况，按模块和事件处理，不要求使用者选择模式：

| 材料情况 | AI 要完成的整理 | 不确定时如何处理 |
|---|---|---|
| 已有埋点表但不标准 | 读取实际表头与合并单元格上下文，将应用、页面、控件、动作、触发时机和负责人映射到标准字段；将确实包含多个动作的原行拆成各一行；保留来源位置 | “事件名称”可能是标识、控件名或业务名称，不能直接机械当作元素名；表内外描述冲突集中确认 |
| 没有埋点表 | 从本期 C 端用户流程梳理页面曝光、关键点击、选择、输入、分享及可观察结果，注明 PRD 证据和触发时机 | 不把 B 端配置、未来规划、删除内容、普通静态展示全部做成事件；不可观察的成功结果不臆造 |
| 部分或全部没有截图 | 逐条使用下方图片优先级，确实缺图时调用脚本按精确应用和页面补图 | 平台没有页面、同名不唯一、没有图片或多图时集中询问，只阻塞相关待确认项 |

已有埋点表优先保留原意。将从 C 端说明发现的漏项标为建议补充，在审核表说明中与原表整理项区分；不悄悄改变用户原有统计口径。一个事件只表达一个触发行为。表格只支持点击/click、曝光/show、输入/input、分享/share，其他业务动作先厘清如何映射，不能把“支付成功”机械替换成点击。

## 2. 平台精确匹配与图片优先级

先限定平台应用，再匹配页面和动作。近似搜索只产生候选；页面名称同名、业务对象不同，或多个候选时请用户决定。APP、微信、支付宝等各端分别使用其平台记录，不跨应用借图。

逐条选择图片：

1. **用户提供的 PRD、关联原型或另附的对应页面图**：下载该原图，标记 `image.source=prd` 或 `user`，后续脚本保留原图。原图暂时无法下载、权限不足或画板尚未导出时标记待获取，不当成缺图改用平台图。
2. **确认该页面没有提供图片**：`image.source=missing` 或省略 image。脚本在用户增长运营平台按应用+页面名称唯一精确匹配，打开“图片信息”，下载 JPG/PNG。记录页面标识、图片来源和下载时间。
3. 平台图仅作已有页面的参考截图，不能证明本期新增控件已上线；描述依据 PRD。图片不符合该事件所在页面、平台无图或匹配不唯一时，列出缺口请用户补充或确认。不生成虚构产品截图。

缺失平台页面先列出应用、页面名称、描述和用户提供的截图。经用户明确要求或确认后执行：

```bash
bash run.sh pages-check --manifest '/绝对路径/pages.json'
bash run.sh pages-run --manifest '/绝对路径/pages.json' --confirmed
```

清单格式为 `{"pages":[{"app":"平台精确应用","name":"页面名","description":"页面描述","imagePath":"./页面.png"}]}`。名称最多30字、描述最多200字；清单和图片变化要重做预检。既没有 PRD 图片又没有平台页面时，先请用户补充图，不能凭空创建页面。页面脚本需要先配置独立审核表地址；可先由助手创建空白独立审核表作为后续目标，绝不把 PRD 链接传给 init。

## 3. AI 草稿交给脚本

在本机任务工作目录准备 JSON，来源位置写到具体章节、表格行或原型页面。脚本支持常见中文列名，但 AI 先解决业务语义，不能期待字段别名自动理解需求。负责人未知时集中询问，不用当前登录人或历史人名填充。

```json
{
  "title": "某需求埋点审核表",
  "sheetName": "埋点审核",
  "events": [
    {
      "app": "平台中确认的应用",
      "page": "平台中确认的页面",
      "element": "提交按钮",
      "action": "点击",
      "developer": "用户指定的开发",
      "tester": "用户指定的测试",
      "description": "用户在填写完成后点击提交按钮时上报。",
      "source": {"kind": "prd-table", "ref": "PRD链接，埋点表第3行"},
      "image": {"source": "prd", "path": "./images/提交页.png", "ref": "PRD第4节截图"}
    }
  ]
}
```

`source.kind` 可为 `prd-table`（原表整理）、`prd-inferred`（从正文提取）、`prepared`（非标准独立表整理）。缺图时改成 `"image":{"source":"missing"}`。JSON 不填 I/J 结果，原表已有事件标识时先明确本次复用或新建范围。

运营平台未配置时询问地址；从配置复用地址不代表自动选择历史业务表：

```bash
bash run.sh platform-init --platform-url '用户确认的事件管理页链接'
bash run.sh check-platform
# 只有平台登录不可用时：bash run.sh platform-login
bash run.sh draft-prepare --manifest '/绝对路径/draft.json' --output '/绝对路径/draft-output'
```

`draft-prepare` 只读查询平台并写本地输出。它校验字段、重复名称、图片内容，按页复用下载，输出 prepared.json、标准表数据和来源记录。`needs_review` 时集中解决 issues，重新生成；不要把不完整结果说成可直接创建。

## 4. 生成独立审核表、核实图片、等待审核

具备本人授权的 lark-cli 时：

```bash
bash run.sh review-create --prepared '/绝对路径/draft-output/prepared.json'
```

此命令只新建独立飞书表格，不接受 PRD 或现有业务表作为写入目标；按 A–J 标准写数据，再把每行图片嵌入 H 列单元格，回读验证字段、空白 I/J 和图片。生成中断时复用本地记录继续同一张表；新建或图片写入结果不明时停止查证，不能反复新建。审核反馈直接修改这张独立审核表；同一草稿内容变化时脚本保留原表并提示处理，不自动另建一份。

没有 lark-cli 时，使用已授权飞书连接或本机浏览器新建独立表，按 review-payload.json 或 review.csv 填入 A–J，将 prepared.json 指向的图片嵌入 H 列。图片文件路径或文本链接不等于单元格图片；必须实际插入，并核对每行可见的图片与字段。工具或登录暂不可用时给出已完成的草稿及具体缺口，不声称已创建在线表。

交付审核表时简要说明事件数量、哪些来自原表/正文、哪些图来自平台以及仍需确认的事项。初始化该表后按 [events-workflow.md](events-workflow.md) 预检，展示范围，用户审核同意后才批量创建。审核后有任何字段或截图编辑，都重新预检。
