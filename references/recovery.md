# 仅在异常时读取

`control.mjs run` 会输出本次日志路径。最多先读取末尾30行；状态摘要用 `control.mjs status`。记录、图片、配置、浏览器会话均为本地私密数据，不上传 GitHub。

- `BROWSER_EXECUTION_PERMISSION_REQUIRED`：已在启动前拦截，尚未运行 Chrome 或提交业务数据。按 [浏览器执行权限](setup.md#浏览器执行权限) 通过宿主正式授权流程执行对应命令，不清除环境标记，不循环原样重试，不要求重新登录。
- 其他浏览器启动失败：区分 Chrome 缺失、宿主限制或已有进程占用，读取对应启动错误；未定位原因前不关闭用户自己的浏览器或重复提交业务操作。
- 登录检查未通过：`control.mjs login` 打开的专用 Chrome 才保存脚本会话。分别确认飞书表格和运营平台都能打开；按终端回车后会再次检查。若显示无权限或网络不可达，解决对应问题，不能当作已登录。
- run.lock：确认没有存活的助手进程才可清理残留锁；不要并发运行两个批次。
- submitting：已在点击前记录。先查平台；找到唯一完整匹配则恢复回写，未找到也禁止再次提交。需要明确证据证明未提交，保留原记录后人工审核恢复状态。
- verified：事件已存在，只补回写。I/J不允许覆盖不同值。输入或截图hash变化时停止核查。
- 页面结构或上传失败：停止整批并保留截图。修复选择器后优先只读验证，不通过重复创建来测试。
- 预检指纹不匹配：表格字段、截图或页面清单在预检后发生变化。重新运行对应的 `events-check` 或 `pages-check`；不得绕过检查直接创建。
- 图片下载依赖飞书UI正常下载授权，Chrome原生下载禁用以避免崩溃，随后使用同一会话读取已授权图片URL。不得复制他人cookie或绕过访问控制。

源表格是单元格图片格式，图片在H列。模板导入飞书后补上单元格图片；也可在本地配置images中给相应行提供原图路径。无需将真实截图提交到仓库。

## 整理、补图、更新异常

- draft-prepare 的 needs_review：按 issues 集中核对原表语义、负责人、精确页面和图片。PRD 已有图但下载失败时获取原图，不改用平台图。
- review-create：本地 data/reviews 中记录新表及每张图片的进度；重试会沿用同一张独立审核表。creating 且无链接表示新建结果不明，先核对云空间，不能删除记录后自动重建。H 列已有其他内容或用户改过字段时保留云端内容，重新审核。
- update-check 不可用：旧版可继续，明确未完成联网检查。确认更新时发布清单变化、文件摘要不符或依赖准备失败会保留原安装；先检查错误，不跳过校验。
- 无本机工具：一次给出首次指南和切换本机的原因，不循环要求使用者自己运行命令。
